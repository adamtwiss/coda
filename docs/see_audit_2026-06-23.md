## BUGS / STRUCTURAL GAPS (actionable)

### S1. SEE capture pruning ceiling at depth=7 — ALL PEERS PRUNE DEEPER

`search.rs`: `if is_cap && depth <= tp(&SEE_CAP_DEPTH)` (default 7, range 3-15).

At depths 8+, Coda does zero SEE-based pruning of losing captures. All 5
reference engines (SF, Reckless, Obsidian, Berserk, Alexandria) apply capture
SEE pruning at all depths with no ceiling.

What peers prune at depth=8 that Coda misses (captHist=0):
- SF: SEE < −1336
- Berserk: SEE < −752
- Obsidian: SEE < −768
- Coda: **nothing**

BNFP (`depth <= 8`) partially covers one depth only and requires the
`static_eval + depth*78 <= alpha` condition to also fire — in balanced
positions it won't.

**Note:** Branch `atlas/s2-see-cap-depth-raise` raised SEE_CAP_DEPTH to 16
and H0'd. But that was on old main with bench 2892640 vs 2944948 — a
different context. Worth re-examining now with current main.

**Fix:** Remove or substantially raise the ceiling. The linear `depth * 120`
formula already scales without a ceiling. SPRT at `[0,3]`.

### S2. SEE quiet pruning missing history adjustment

`search.rs` ~line 3902–3925:
```rust
let see_quiet_threshold = -tp(&SEE_QUIET_MULT) * lmr_d * lmr_d;
```
`lmr_d` is purely table-based. No history adjustment.

Every engine ranked above Coda uses history to make the threshold move-specific:
- **SF**: `lmrDepth += (contHist + mainHist*71/32) / 2995; SEE >= -25*d²`
- **Obsidian**: `lmrDepth = depth - table + hist/3516; SEE >= -21*d²`
- **Reckless**: `SEE >= -16*d² + 52*d - 21*hist/1024 + 22` (hist directly in formula)
- **Alexandria**: lmrDepth includes hist; `SEE >= -98*d`
- **Coda**: `SEE >= -30*d²`, no history

Effect: moves with good history should get a more permissive threshold (search
even if slightly SEE-negative); bad-history moves should be pruned more
aggressively. Coda applies the same threshold regardless. SPSA has compensated
by converging SEE_QUIET_MULT to 30 (slightly above peers' ~21-25) but can't
recover the lost discrimination.

**Fix:** Compute hist score before SEE site; adjust lmr_d:
```rust
let hist_score = /* main hist + cont hist contributions */;
let lmr_d_adj = (lmr_d - hist_score / tp(&SEE_HIST_DIV)).max(0);
let see_quiet_threshold = -tp(&SEE_QUIET_MULT) * lmr_d_adj * lmr_d_adj;
```
New tunable SEE_HIST_DIV (~3000-8000 range based on peers). Retune-on-branch
for SEE_QUIET_MULT + SEE_HIST_DIV after structural change.

### S3. BNFP missing captured piece value

Coda BNFP: `static_eval + depth * BAD_NOISY_MARGIN <= alpha`

SF capture futility: `static_eval + 218 + 223*lmrDepth + PieceValue[captured] + 131*captHist/1024 <= alpha`
Reckless: `eval + 71*depth + 69*hist/1024 + 81*piece_value/1024 + 25`

Without captured piece value, Coda can prune high-value captures in losing
positions. Example: eval 100cp below alpha, considering QxR (+400cp material).
At d=4: `100 + 4*78 = 412` might exceed alpha_delta and prune it; SF/Reckless
add the rook value to the margin so they don't.

Captured piece type is already computed at the call site.

**Fix:** Add `see_value(captured_pt)` to the BNFP margin check. One-liner.

### S4. Pinned-piece filtering absent in SEE

`see.rs`: Pinned pieces are counted as valid recapturers even if they can't
legally move.

| Engine | Pin filtering |
|--------|-------------|
| SF (#1) | YES — blockersForKing exclusion |
| Reckless (#2) | YES — pinned mask |
| Obsidian (#4) | YES — pinned mask |
| Berserk (#3) | No |
| Coda (#7) | **No** |

Causes SEE over-optimism: some exchanges classified as winning/neutral are
actually losing because the apparent recapturer is pinned. Coda already
computes pinned masks in is_legal — plumbing them through to SEE is feasible.

**Fix:** Add `&& !(pinned & (1u64 << att_sq))` in attacker selection loop.
SPRT at `[-2, 1]` (correctness fix). Berserk (#3) also lacks this and still
outranks Coda, so it may be low Elo.
