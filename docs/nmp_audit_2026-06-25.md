## THE CRITICAL FINDING: R CLAMP FIRES AT ALL DEPTHS

Coda's null search floor is `max(1, depth - R)`. With BASE_R=8, the clamp fires at:
- depth=4: R=8 → clamped to depth-1=3 → null search at depth **1**
- depth=6: R=8 → clamped to 5 → null at **1**
- depth=8: R=10 → clamped to 7 → null at **1**
- depth=10: R=12 → clamped to 9 → null at **1**
- depth=12: R=12 → clamped to 11 → null at **1**

**Every null search goes to exactly depth 1.** The depth and eval terms are irrelevant — the base consumes the entire budget.

Peers allow QS null searches (depth goes to 0 or negative):
| Engine | null depth at d=6 | null depth at d=8 |
|--------|------------------|------------------|
| Stockfish | QS (depth -3) | QS (depth -1) |
| Reckless | QS (depth -1) | depth 1 |
| Berserk | depth 0 | depth 0 |
| Alexandria | depth 0 | depth 2 |
| PlentyChess | depth 2 | depth 4 |
| **Coda** | **depth 1** | **depth 1** |

QS null searches catch tactical threats (captures, checks in QS). Coda's depth-1 searches
miss these, making null move verification less discriminating at shallow depths.

**Why the SPSA drifted here:** With the clamp always firing, the only tunable that matters
is BASE_R (controls the clamp point). SPSA raised it to 8 to always force depth-1, since
that was the local optimum. The DEPTH_DIV and EVAL terms became irrelevant noise.

**Fix:** Lower BASE_R from 8 toward 4-5 AND remove/raise the clamp floor from 1 to 0
(allow QS null searches). This requires a full retune since the formula changes fundamentally.
Expected bench change: LARGE (many more null searches will drop into QS and cut off).

### N2. IIR fires BEFORE NMP — unique among all 6 peers

Coda's move loop ordering: IIR (line ~3417) → NMP (line ~3601).
All 6 peers: NMP fires at full depth; IIR only applies to the regular moves loop.

Effect: at cut nodes with no TT move where IIR fires, NMP uses depth-1 instead of
the intended depth. The null search is one ply shallower than specified by the formula.
SPSA has calibrated around this but it's a structural divergence.

**Fix:** Reorder IIR to after NMP. One-line code move. SPRT `[0, 3]`.

---

### N3. Verification threshold = depth 10 — peers use 14-16

Coda fires a full verification re-search at depth ≥ 10. Peers:
- SF/Reckless: ≥ 16
- Berserk: ≥ 14
- Alexandria/PlentyChess: ≥ 15

Coda pays an expensive verification negamax call at d=10-13 where no peer does.
This is conservatism that costs compute without equivalent coverage in peers.

**Fix:** Raise NMP_VERIFY_DEPTH_10X from 104 (=10) toward 140-160 (=14-16).
SPRT `[0, 3]` (should gain from eliminating unnecessary verification).

---

### N4. Missing depth-relaxed eval gate

Coda: `static_eval >= beta + nmp_threat_margin` (always strict).
SF: `static_eval >= beta - 16*depth - 53*improving + 378` → allows NMP when eval is modestly BELOW beta at high depth.
Reckless: similar depth-scaled gate.
Obsidian: `static_eval + 22*depth - 208 >= beta`.

Coda never fires NMP when eval is below beta, even at high depths where a relaxed gate
is safe. Could miss NMP opportunities in quiet high-depth positions.

**Fix:** Add depth bonus: `static_eval + k*depth >= beta + nmp_threat_margin`.
New tunable NMP_DEPTH_GATE_K (default 0, range 0-50). SPRT `[0, 3]`.

---

### N5. Missing Reckless TT-capture guard

Reckless skips NMP when TT has a Lower-bound entry with a capture ≥ knight value:
positions where the best known move is a strong capture are tactically sharp and null
moves are unreliable.

Coda lacks this. Obsidian alternative: add +1 to R when TT move is noisy (less disruptive).

**Fix option A:** Skip NMP when `tt_hit && tt_entry.flag == TT_FLAG_LOWER && tt_move_noisy`.
**Fix option B:** Add R+1 when TT move is noisy (Obsidian approach).
SPRT `[-1.5, 1.5]` for either.
