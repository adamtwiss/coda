## CONFIRMED BUGS / CORRECTNESS DEVIATIONS

### QS-B1. Beta blending applied AFTER TT store (wrong order)

`search.rs:5184–5202` non-check path:
```rust
let store_score = score_to_tt(best_score, ply);   // ← unblended
info.tt.store(..., store_score, ...);              // ← TT gets higher value
// THEN blend for return:
if best_score >= beta && beta - alpha_orig == 1 {
    return (best_score + beta) / 2;               // ← parent gets lower value
}
```

All 5 reference engines blend FIRST, then store:
- SF: `bestValue = (bestValue + beta) / 2;` then `ttWriter.write(...)` (line 1727)
- Reckless: blend in-place then `td.shared.tt.write(...)` (line 1283)
- Obsidian/Alexandria: identical blend-first pattern

Result: TT stores an inflated lower bound. When re-probed, the calling negamax
gets the unblended (higher) score as a TT cutoff — slightly over-optimistic
propagation.

**Additional:** The **in-check (evasion) path** has NO beta blending at all
(`search.rs:5012–5021`). SF/Reckless/Obsidian/Alexandria apply the same blend
uniformly for both in-check and not-in-check. Coda is inconsistent.

**Fix (branch qs/blend-before-store):**
1. Non-check: blend `best_score` in-place BEFORE calling `score_to_tt` and storing.
2. Evasion: add the same blend before store/return.

Bounds: `[-2, 1]` (correctness fix, direction uncertain).

### QS-B2. CANCELLED — SEE_MATERIAL_SCALE=215 is correct, not a bug

Initial audit read the 2.15× as inflating the delta margin. This is wrong.

**Context:** Coda uses traditional SEE piece values (pawn=100, knight=330,
rook=500, queen=950) inherited from classical engines. However, Coda's NNUE
eval is NOT in traditional centipawns — it is trained on LC0 WDL data where
+100 eval ≈ 50% win probability, not "1 pawn material." The `stand_pat` and
`alpha` values are in this WDL-calibrated NNUE scale.

The delta pruning comparison is:
```
stand_pat [NNUE units] + see_value(cap_pt) [classical cp] × SEE_MATERIAL_SCALE/100 + margin <= alpha [NNUE units]
```

`SEE_MATERIAL_SCALE=215` is the SPSA-converged unit conversion factor that
makes classical SEE values commensurable with NNUE eval units. Reducing it to
100 would BREAK the delta pruning by comparing apples to oranges.

Other engines (SF, Reckless, etc.) have the same conceptual problem — their
piece values and eval scales are co-tuned until the delta margin "works," but
the scale mismatch is implicit. Coda makes it explicit via `SEE_MATERIAL_SCALE`.

**Open question:** Whether 215 is still the right value given the current
production net's EVAL_SCALE, or whether SPSA has drifted. A focused retune of
`SEE_MATERIAL_SCALE` + `QS_DELTA_MARGIN` together on trunk against the current
net would resolve this — leave to next full-sweep SPSA pass.

## STRUCTURAL DIVERGENCES (untested, worth probing)

### QS-S1. Delta pruning doesn't update `best_score` to `max(best_score, futility)`

SF (line 1664): `bestValue = std::max(bestValue, futilityValue);` after
delta-pruning a capture. Obsidian does the same. When all QS captures are
delta-pruned, Coda returns raw `stand_pat` rather than
`max(stand_pat, stand_pat + capture_value + margin)`. The difference is capped
at `QS_DELTA_MARGIN` cp and probably tiny in practice, but it's a consensus
divergence from SF/Obsidian.

### QS-S2. Stand-pat beta cutoff not cached to TT

When QS returns early from stand-pat (`best_score >= beta`), no TT store.
SF/Reckless store `TT_FLAG_LOWER` with `Move::none()` at that point when there
was no prior hit. Coda only stores at end of capture loop. Low priority
(stand-pat cutoff positions are often hit transiently).

### QS-S3. Quiet checks at QS depth 0 (untested on Coda)

Obsidian and Berserk generate quiet checks at initial QS depth (depth=0).
SF removed this long ago. Reckless doesn't. Low-cost probe if we want to test.

### QS-S4. QS history updates on beta cutoff (untested)

Reckless/Berserk update capture/quiet history from QS beta cutoffs. SF/Alexandria
don't. Mixed signal; probably low prior given SF doesn't do it.
