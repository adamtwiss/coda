## TIER 1: Structural gaps (new DOF, not tunable by SPSA on current code)

### L1. Missing LMR_BASE offset — HIGHEST PRIORITY

**Coda formula:** `int(ln(d) * ln(m) / C_QUIET)`, no base. C_QUIET=1.44 SPSA-tuned.

**All peers above Coda:** `base + ln(d)*ln(m)/C` with positive base for quiets:
- Obsidian: base=0.99, C=3.14
- Alexandria: base=1.07, C=2.27
- Berserk: base=0.24, C=2.04
- Stockfish: effective base ~1.11

**The structural problem:** Without a base, SPSA drove C_QUIET down to 1.44 (peers: 2.0–3.1)
to lift shallow-node reductions. But lowering C steepens the deep end simultaneously.
SPSA cannot solve both constraints with a single parameter. Result: a deadzone at
d=3-5, m=3-8 (highest-frequency inner-tree) where Coda reduces 0 moves that peers
reduce by 1-2:

| (d,m) | Coda | Berserk | Obsidian | Alexandria | SF |
|-------|------|---------|----------|-----------|-----|
| 3,3   | 0    | 0       | 1        | 1         | 2  |
| 3,8   | 1    | 1       | 1        | 2         | 2  |
| 4,4   | 1    | 1       | 1        | 1         | 2  |
| 5,5   | 1    | 1       | 1        | 2         | 2  |

**Fix:** Add `LMR_BASE_QUIET` tunable (default 0, range 0–150 stored as /100, e.g. 50→0.50).
Initialize: `base/100.0 + ln(d)*ln(m)/C`. Expose C_QUIET range to 80-300 so SPSA
can find the correct (BASE, C) pair jointly. Retune-on-branch required — changing
the base shifts the entire table.

Estimated Elo: medium-high. This is the "missing second DOF" from the ltc_audit.

### L2. Next-ply cutoff count missing

Both SF and Reckless track `cutoff_count[ply+1]` — how often the next ply produced
an early beta cutoff. When this is high, later moves at the current node are less
promising → increase reduction.

**SF (L1228):** `if (ss+1)->cutoffCnt > 1: r += 251 + 1124*(>2) + 1042*allNode`
**Reckless (L817):** `if cutoff_count > 2: reduction += 1604`

**Coda:** No `cutoff_count` field in SearchInfo stack at all.

**Implementation:** Add `cutoff_count: [i32; MAX_PLY+1]` to SearchInfo.
- Reset two plies ahead at node entry: `info.cutoff_count[ply_u + 2] = 0`
- Increment on cutoff: `info.cutoff_count[ply_u] += 1` (after beta cutoff, before return)
- LMR gate: `if info.cutoff_count[(ply+1).min(MAX_PLY)] > 2 { reduction += 1; }`

Pure free information — no extra search cost. SPRT at `[0,3]`.

### L3. TT score < alpha missing from quiet LMR

**Reckless (L821):** `if tt_score < alpha && is_valid(tt_score): reduction += ~0.6`
Rationale: prior search at this position failed low → later moves here less promising.

**Coda:** No equivalent. `tt_pv` goes the opposite direction (reduce less). No "prior
fail-low" tightening.

**Fix:** `if tt_score < alpha && tt_score.abs() < MATE_SCORE - 100 { reduction += 1; }`
One-liner. SPRT at `[0,3]`.

## TIER 3: Tuning gaps (present, but wrong calibration or partial)

### L6. `!is_pv` vs `cut_node` in cut-node adjustment

**Coda (L4252):** `if !is_pv && move_count > 1: reduction += 1`
Comment says "cut nodes" but `!is_pv` catches ALL zero-window nodes — both
expected cut-nodes AND all-nodes.

**SF:** Separate `if cutNode: r += 3611 + 985*!ttMove` (large, TT-move-aware).
**Reckless:** `if cut_node: reduction += 1762 + 2116*tt_move.is_null()`.

Both peers: (a) use the actual `cut_node` bool not `!is_pv`, (b) add extra reduction
when there's no TT move (stronger prior that the position is a cut). Coda misses
both distinctions.

**SF also has all-node scale:** `if allNode: r += r * 273 / (256*depth + 260)`.
Coda has no confirmed all-node detection (would need to track that no move raised
alpha so far at this node).

### L7. Main history ×1 vs ×2 in stat score

**SF (L1239):** `statScore = 2 * mainHistory + contHist[0] + contHist[1]`
**Coda (L4300):** `hist_score = main_score + cont@ply-1 + cont@ply-2/2 + pawn_hist`

Coda uses ×1 main history (vs SF ×2). Also ply-2 at half-weight (vs SF full weight).
These are tuning parameters but the ×1 vs ×2 main history discrepancy is concrete.
Worth testing: `hist_score = 2 * main_score + cont1 + cont2/2 + pawn_hist`.

### L8. doDeeper margin uses reduction-scaling (unique to Coda)

**Coda:** `do_deeper if lmr_score > best_score + 60 + 10 * reduction`
**Peers:** flat or depth-scaled (SF: +48 flat; Alexandria: +77 + 2*newDepth)

The `+10*reduction` means moves with higher reduction (likely bad moves) need to
beat best_score by more to trigger do_deeper. Logically defensible but at r=3+,
threshold=90 vs SF's 48 — potentially under-triggering do_deeper. Untested.

### L9. Root-depth LMR effective range too narrow

`(root_depth - LMR_ROOT_THRESH=16) * LMR_ROOT_COEF=11 / 100` — integer truncation
means it activates only at root_depth ≥ 26 (to subtract 1 ply). At typical LTC
play (root_depth 20-25) the feature is dormant. Lowering LMR_ROOT_THRESH to ~10
would make it active at normal LTC search depths. Worth a SPSA probe.
