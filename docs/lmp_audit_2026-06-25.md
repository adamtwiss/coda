# Late Move Pruning (LMP) Audit — Coda vs top-6 (2026-06-25)

Cross-engine audit of Coda's movecount-based LMP against the six stronger
reference engines (Stockfish, Reckless, Berserk, Obsidian, PlentyChess,
Alexandria). Method: extract each engine's exact LMP formula, counter basis,
gating, and history/improving handling; compare to Coda's `src/search.rs`
move-loop block (~L4128).

## Coda's scheme (baseline)

```rust
if ply > 0 && !in_check && depth >= 1 && depth <= LMP_DEPTH(8)
    && !is_cap && !is_promo
    && (depth >= 4 || !board.gives_direct_check(mv))
    && best_score > -(MATE_SCORE - 100) {
    let lmp_limit = (LMP_BASE(5) + depth*depth) / (2 - improving as i32);
    if move_count > lmp_limit { skip_quiets = true; picker.skip_remaining_quiets(); continue; }
}
```

- **Formula** `(5 + d²) / (2 − improving)`, prune when `move_count > limit`.
- **Counter**: `move_count` = ALL moves (incremented pre-pruning). ✓ consensus.
- **improving**: boolean divisor `(2 − improving)` → improving doubles the budget.
- **Runs on PV nodes** (the `!is_pv` gate was removed, SPRT #1209 +5.0).
- **Hard depth cap** `depth ≤ LMP_DEPTH(8)`.
- **Check carve-out**: protect `gives_direct_check` moves only at `depth < 4`
  (SPRT #1227 +1.3).
- **No history** in the threshold. Coda has NO standalone history-pruning block
  (tried + removed, #1697 H0 −6.8 — "doesn't fit Coda's search/eval shape");
  history IS folded into futility + SEE-cap margins instead.

## Correctness / quality

**No bugs found.** Counter basis (all-moves), pre-make placement, `skip_quiets`
sticky-flag mechanism, mate guard, and PV coverage all match consensus. Code is
clean and well-commented (the LMP_BASE comment even records the prior 9→5
cross-engine bisect).

Two pieces of **arguably-better engineering** vs the references:
- The explicit `depth ≤ 8` cap *removes* per-node work at high depth where the
  `d²` term means LMP can never bind anyway. All 6 refs run the block at every
  depth and rely on `d²` self-limiting → strictly more work. **Keep the cap.**
- The depth-gated check carve is a tuned middle ground between Reckless
  (protect ALL direct checks) and SF/Berserk/Obsidian/Alex/Plenty (no carve).

### The one consistent divergence: Coda's shallow LMP is the most LENIENT of all 7

Coda combines three leniency sources vs the SF/Obsidian consensus
(`moveCount >= (3+d²)/(2−i)`):
1. **LMP_BASE = 5 vs 3** (already bisected down from 9; still above consensus).
2. **`>` not `>=`** — searches one extra move at the same limit.
3. Same `d²`/divisor shape otherwise.

Worked example, depth 2, not-improving:
- Coda: limit `(5+4)/2 = 4`, prune when `move_count > 4` → searches **4** quiets.
- SF/Obsidian: `(3+4)/2 = 3`, prune when `moveCount >= 3` → searches **2** quiets.

So at shallow depth Coda searches roughly **2× the quiets** the pack does before
LMP bites. Every one of the six engines above Coda prunes harder here. This is
the single coherent, un-probed-in-isolation consensus signal.

## Experiments (ranked)

**E1 — LMP_BASE 5 → 3 (primary).** Pull Coda's shallow leniency to the
SF/Obsidian consensus value. Single-param, direct `[0,3]` STC SPRT. Rationale:
all 6 reference engines prune harder at shallow depth; the LMP_BASE comment
shows the 9→5 bisect was a flat win, and 5→3 is the natural continuation.
Memory `project_rfp_lmp_flat_wins` says LMP_BASE 8→5 was +1.7/+2.8/+4.1 across
TCs — isolate the single param; restart-from-low can beat the SPSA local max.
Risk: SPSA had range [1,15] and sits at 5, so 3 may regress; cheap to find out.

**E2 — `>` → `>=` (fold into E1 or test alone).** Aligns with the 4/6 that use
`>=`; equivalent to ~base−1. Cleanest as a combined "tighten shallow LMP" branch
with E1, or a standalone bisect step if E1 is interesting but overshoots.

**E3 — improving steeper-quadratic (Berserk/Alexandria shape).** Replace the
flat `÷(2−improving)` (constant 2× budget at every depth) with an
improving-dependent `d²` coefficient, so the improving budget grows faster with
depth like the two table engines. Adds one tunable (`LMP_IMPROVING_MULT`).
Medium value, knob-risk — only after E1/E2 resolve.

**Not pursuing:**
- **Remove the depth cap** — NPS-negative (runs the block at d>8 where it never
  binds) and Elo-neutral; the cap is correct.
- **History-in-LMP** (Reckless/Plenty, 2/6) — standalone history-pruning already
  H0'd −6.8 in Coda (#1697); history-driven movecount relaxation is the same
  signal that doesn't fit. Strong prior against.

## Deeper dive: WHY does SPSA keep LMP_BASE high (blunt)?

Adam's observation: lower LMP_BASE values are tried but SPSA pushes the param
back up each subsequent tune — the "tuner detunes to compensate for a structural
issue" signal (Feature Improvement Cycle). Investigated three hypotheses with
instrumented bench (depth 12, prune counts are deterministic):

```
RFP cutoffs:    30.1% of nodes (301/Kn)   <- very aggressive, same depth band as LMP
SEE prunes:     316978 (141.8/Kn)         <- 3x LMP's volume
LMP prunes:     114528 (51.2/Kn)
Futility:        29496 (13.2/Kn)
Move ordering:  avg cutoff pos 1.37, first-move 84.2%
```

- **(C) Bad ordering → REFUTED.** 84.2% first-move cutoffs, avg cutoff 1.37 —
  Coda's ordering is strong; good late quiets are not systematically buried.

- **(B) Competing pruner + order inversion → CONFIRMED structural.** Coda's
  quiet-pruner order is SEE-quiet → futility → **LMP last**. SF/consensus run
  **LMP first** (moveCountPruning sets skipQuiets before SEE/futility). Because
  LMP is last in Coda, its `move_count > limit` only fires on quiets that already
  survived the SEE (142/Kn) and futility filters — a pre-filtered residual of
  non-losing quiets. Count-pruning a non-losing residual is riskier than
  count-pruning the raw quiet stream → SPSA keeps BASE high. RFP (30% of nodes)
  and SEE-quiet (3× LMP volume) operate in the same depth≤8 band and cream off
  most of what LMP would otherwise catch.

- **(A) Missing non-pawn-material guard → CONFIRMED gap.** Coda already computes
  `stm_non_pawn` (used to gate NMP for zugzwang) but the shallow-pruning block
  (RFP at L3531, LMP at L4138, futility at L4105) has **no** `hasNonPawns(stm)`
  guard. SF (`pos.non_pawn_material(us)`), Obsidian (`hasNonPawns(sideToMove)`)
  and PlentyChess (`board->hasNonPawns()`) all gate their entire shallow-pruning
  cluster on it. In pawn-only / few-piece endgames the late king/pawn quiets are
  the critical resources; pruning them by count or eval occasionally drops a
  winning/drawing move → globally SPSA blunts LMP to limit the damage.

**Conclusion:** LMP doesn't intrinsically "want to be blunt" — the high BASE is
most likely compensation for (A) the missing endgame guard and (B) the LMP-last
ordering. The principled fix is to add the guard and/or reorder LMP first, which
should let BASE fall to consensus AND prune more in the safe middlegame.

### Revised experiment set (structural-first)

- **A `lmp/nonpawn-guard`** — add `stm_non_pawn != 0` to the LMP gate
  (SF/Obsidian/Plenty consensus). Expect neutral-to-positive standalone; the real
  win is that it should let BASE retune downward.
- **B `lmp/first-order`** — move the LMP block ahead of SEE-quiet + futility
  (SF Step-14 order). Tree-shape-changing → retune candidate if neutral.
- **C `lmp/tighten-consensus`** — LMP_BASE 5→3 + `>`→`>=` (E1+E2). Control: if
  this regresses while A/B don't, it confirms the leniency is compensatory.
- **D `lmp/improving-quad`** — E3 improving-steeper-quadratic via one tunable
  `LMP_IMP_MULT` (×10, default 10 = bench-identical), letting SPSA give the
  improving budget a steeper d² slope (Berserk/Alexandria shape).

## Expectation setting

LMP is one of Coda's most-tuned features (PV-gate removal +5.0, check-carve
+1.3, LMP_BASE 9→5 bisect). Like the QS / extensions / ProbCut audits, the most
likely outcome is confirmation that the scheme is well-fitted. E1 is worth firing
because it's a single cheap param, the consensus signal is real and one-directional,
and prior "isolate the lenient knob" probes (RFP_DEPTH, LMP_BASE 8→5) found flat
wins SPSA's local max had missed.
