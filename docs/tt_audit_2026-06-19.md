## ROOT CAUSE: eval-seed stubs flood the TT at small Hash sizes

**Agent 3, Finding 1 — structural bug explaining the observed small-TT regression.**

`search.rs:3309-3311`:
```rust
if !tt_hit && FEAT_TT_STORE.load(Ordering::Relaxed) {
    info.tt.store(board.hash, -2, -INFINITY, TT_FLAG_UPPER, NO_MOVE, raw_eval, is_pv);
}
```

Every node that misses the TT writes a `depth=-2` stub to cache the eval and avoid
re-evaluating on revisit. Under a large TT, stubs fill otherwise-empty slots (benefit).
Under a small TT:

- At 16MB: 1,310,720 total slots. A depth-30 search visits ~50M nodes; 20-30M miss TT
  → **15–23× TT oversubscription from stubs per search**. The entire table cycles
  multiple times.
- Eviction: a freshly-written stub scores `depth=-2 - 0×8 = -2`. A depth-15 entry from
  3 searches ago scores `15 - 3×8 = -9`. **The stub wins** — the deep entry is evicted.
- SF, Reckless, Obsidian, Berserk, Alexandria write ZERO eval stubs. Every slot holds a
  genuine search result. SF retains an order of magnitude more depth≥10 entries per slot.

The 5-slot bucket advantage (vs peers' 3-slot) is completely erased by the stub flood.

**Fix options (branch T1):**
1. Gate eval-seed write on `is_pv` — eliminates 97%+ of stub writes (PV ≈ 1/BF ≈ 2.5%
   of all nodes) while preserving the caching benefit on lines that matter.
2. Remove eval-seed writes entirely — accept the small NNUE re-eval cost; peers do this.
3. Write only when slot is empty — zero-cost write if bucket has a free slot.

Recommended: start with (1) as the least invasive; if bench delta is small, try (2).

## TT STORE BUGS (every peer has these; Coda doesn't)

### T2. Missing TT move preservation at all-nodes

**Agent 1, Finding B — all 5 peers implement this; Coda doesn't.**

When an all-node stores (flag=UPPER, best_move=NO_MOVE), Coda packs NO_MOVE into
new_data and overwrites the bucket slot — erasing whatever best_move was stored there
by a prior deeper iteration.

SF:
```cpp
if (m || uint16_t(k) != key16)
    move16 = m;  // keep old move when new move is null AND same key
```
Reckless:
```rust
let best_move = if best_move == Move::NONE && key == entry.key {
    entry.best_move  // preserve
} else { best_move };
```

Failure mode: depth-10 iteration stores `best_move=Nf3`. Depth-6 all-node comes through,
stores `best_move=NO_MOVE` → Nf3 is erased. Next visit: no TT move, no IIR, worse
ordering. Estimated +1–3 Elo.

**Fix (tt.rs, ~5 lines):** In the same-key update path, read existing move from slot
data and use it when `best_move == NO_MOVE`.

### T3. Missing EXACT-bound override in replacement

**Agent 1, Finding A / Agent 3, Finding 2 — all 5 peers have this; Coda doesn't.**

Coda same-key update (`tt.rs:472-478`): only overwrites when
`depth > slot_depth - 3 || gen != slot_gen`.

All peers unconditionally overwrite when new bound is EXACT:
```cpp
// SF:
if (b == BOUND_EXACT || key != e->key || d > e->depth - 4 || e->age() != gen)
```

Result: a new EXACT result at depth=5 cannot replace a stale LOWER/UPPER at depth=8
(5 > 8-3=5 → false). The more precise EXACT score is discarded. Estimated +1–2 Elo.

**Fix (tt.rs, 1 line):** Add `|| flag == TT_FLAG_EXACT` to the same-key overwrite
condition.

## TT PROBE GAPS

### T4. cut_node TT cutoff guard enforced at all depths; Reckless relaxes at depth>5

**Agent 2, Finding F2 — medium priority.**

Coda (`search.rs:3095`):
```rust
if !tt_cut_is_pv && cut_node == score_above_beta && bound_matches && halfmove_ok {
```

Reckless applies `cut_node == score_above_beta` only at depth ≤ 5; at depth > 5 it
takes any-direction TT cutoff regardless:
```rust
match tt_bound {
    Upper => tt_score <= alpha && (!cut_node || depth > 5),
    Lower => tt_score >= beta  && (cut_node  || depth > 5),
}
```

At deep nodes, Coda skips valid TT cutoffs that Reckless takes. Estimated +0.5–2 Elo.

**Fix (search.rs, 1 line):** Add `|| depth > 5` to both the cut_node and !cut_node
clauses, matching Reckless's pattern. Gate behind depth check to avoid shallow-depth risk.

### T5. QS PV nodes block ALL TT cutoffs; peers only block decisive EXACT

**Agent 2, Finding F9 — low priority.**

Coda gates all three bound types (EXACT, LOWER, UPPER) behind `!qs_is_pv`. Reckless
only blocks EXACT at PV nodes when score is decisive; LOWER/UPPER QS cutoffs at PV
proceed freely. Extra QS work at PV nodes. Estimated +0.5 Elo.

## LOWER PRIORITY

### T6. Power-of-2 TT masking wastes up to 50% RAM at non-power-of-2 Hash sizes

Coda uses `hash & (num_buckets - 1)` requiring power-of-2 bucket count, silently
rounding down. Hash=96MB → 64MB effective (33% waste). Hash=512MB on some systems → 256MB.
All peers use `mul_hi64` which works with arbitrary sizes. No Elo impact at OB standard
sizes (Hash is always power-of-2 in practice) but confusing for users.

### T7. No TT_PV retention bonus in replacement threshold

Coda: `depth > slot_depth - 3`
Peers: `depth + 4 + 2*is_pv > slot_depth`

PV nodes get a 2-ply protection bonus from peers that Coda lacks. Low priority.
